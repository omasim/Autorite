# Governance and Workflow
## Change classes
Research content; scientific correction; baseline amendment; legacy archaeology; site/editorial; infrastructure.

## Baseline amendment
Never silently edit frozen baseline. Record reason, old/new text, affected packages, whether results were already observed, and migration impact.

## PR epistemic checklist
What changed? Which object types? Evidence/result basis? Scope/assumption changes? Claims challenged/superseded? Public pages affected? Confirmatory/exploratory/correction/infrastructure? Baseline amendment required?

## Main protection
Require PR and status checks; block force pushes/deletion. Prefer linear history. For initial solo work, automated checks + explicit self-review are acceptable; foundational claims should later seek external review.

## Suggested labels
question, claim, experiment, formal, empirical, legacy, collision, decision, correction, blocked, synthesis, site, review.

GitHub project-management status never replaces canonical epistemic status in versioned records.
